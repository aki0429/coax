# Sony torne（CECH-ZD1 J）の受信安定化

このフォークは [Till0196/coax](https://github.com/Till0196/coax) を元に、Sony CECH-ZD1 JのDiB8096復調器で一部チャンネルの選局が失敗する問題を改善したものです。上流のコードとライセンス表示を引き継いでいます。

対象はcoaxの `cech-zd1j` バックエンドです。別プロジェクトのLinuxカーネルドライバー `torne_drv` を変更したものではありません。

## 症状と変更内容

検証したWindowsの実機では、読売テレビ・NHK総合大阪・NHK総合京都・KBS京都などが `no_lock` になり、TVTestから選局できないケースがありました。受信できる局もあったため、復号処理より前の選局・復調器の取得処理を調べました。

1. **復調器の選局ステップ間隔を10msから100msへ戻しました。** 移植元のLinuxの待機間隔に合わせ、FFT探索とガード区間探索が早すぎるタイミングで進むことを避けます。
2. **ロックできなかった探索を、最大3回までやり直します。** 各試行前にチャンネルのプロパティキャッシュを初期化し、前回取得途中のパラメーターを使って探索を省略しないようにしました。再試行間には100ms待ちます。
3. **再発防止テストを追加しました。** FFTの結果が安定する前にガード探索を開始すると失敗する模擬チップと、最初の探索に失敗しても次の探索で受信できるケースを確認します。

I2C/USBの通信エラーと復調状態機械のタイムアウトは、成功に見せずエラーとして返します。再試行は1回の選局につき合計3試行までで、成功した時点で終了します。

変更ファイル:

- `internal/coaxd/demod/dib8096/dib8000_tune.go`
- `internal/coaxd/demod/dib8096/board.go`
- `internal/coaxd/demod/dib8096/dib8096_test.go`

## 実機での確認結果

2026年10月27日、Windows 11 x86-64、WinUSB、CECH-ZD1 J 1台で確認しました。選局の比較元は上流v0.1.0、修正のベースは上流コミット `2d9f2c263a3b080ecef3a8ede1eb86c6afa48405` です。

まず各周波数のストリームと局情報を取得し、BonDriver_coax経由で主要9局を連続受信しました。読売テレビ・NHK大阪・NHK京都を2巡した後に残り6局を選局した、合計12回の短時間試験はすべて成功しました。

さらに各周波数をTVTest 0.10.0 x64で約6秒ずつ検証録画し、ffprobeのフレーム解析で映像・音声の両方を確認しました。単に局名が一覧に出たことを「視聴確認」とはしていません。

## 利用・ビルド

既存のcoaxの導入手順と [CECH-ZD1 Jの説明](cech-zd1j.md) に従います。Goの必要バージョンは、このフォークの `go.mod` を参照してください。

```sh
go build -o coax ./cmd/coax
go build -o coaxd ./cmd/coaxd
go test ./internal/coaxd/demod/dib8096
```

Windows用のファイル名を明示する場合:

```powershell
go build -o coax.exe ./cmd/coax
go build -o coaxd.exe ./cmd/coaxd
```

WindowsでTVTest/BonDriver_coaxを利用する場合は、実際に起動される `coaxd.exe` をこのフォークからビルドしたものに置き換えます。複数フォルダーに古い `coaxd.exe` がある場合は、読み込まれる場所に注意してください。BonDriver側のチャンネル順とTVTestの `.ch2` の番号も一致させる必要があります。

このフォークが提供する変更は選局・受信の処理です。TVTest、BonDriver、復号用の別ソフトウェア、鍵、録画データは同梱していません。

## ソフトウェアテストの結果

`go test ./internal/coaxd/demod/dib8096 ./internal/coaxd/usb/board/cechzd1j` は成功しました。DiB8096の既存テストに加え、待機間隔と再探索の回帰テストを含みます。

Windows上の `go test ./...` は全件成功していません。以下のパッケージの失敗は、同じWindows・同じチェックアウト改行条件の未修正ベースでも再現しました。

- `internal/coaxd/host/daemon`: OS別のパス表記のテスト
- `internal/coaxd/host/hostapi` / `pkg/host`: 改行に依存するJSONフィクスチャーのハッシュ検査
- `internal/coaxd/pcie/tbs`: モードと搬送波方式の整合性検査
- `internal/coaxd/pcie/windriver`: バージョン文字列の判定
- `pkg/usbio/injected`: Windowsでのテスト用ファイルの後片付け

全体実行時には `internal/idle` の時間依存テストも1回失敗しましたが、未修正ベースでの単独再実行では成功しました。これらの未解決事項を含め、プロジェクト全体のテスト成功を主張するものではありません。このフォークの変更範囲はtorneの選局処理です。

## 制限

- 実機確認はWindowsのCECH-ZD1 J 1台です。Linux・macOSや他個体で同じ改善が出ることまでは確認していません。
- 待機時間が増えるため選局は遅くなります。ロックに失敗すると再試行分の時間もかかります。再試行で受信できない電波を受信可能にするものではありません。
- 22ch・26chは検証環境で信号が弱く、フルセグの映像・音声は確認できませんでした。今回の結果を、他の受信設備や地域で受信できないことの証明とはしていません。
- 各約6秒と短時間の連続選局試験による結果です。長時間録画の無停止性や、あらゆる信号条件での安定動作を保証するものではありません。
- CECH-ZD1 JはISDB-T用です。この修正でISDB-CやBS/CSに対応するわけではありません。
