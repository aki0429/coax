# WindowsでTVTestを2つ起動したときのSonyチューナー割り当て

## 対象の症状

同じWindows PCへSony CECH-ZD1 Jを複数台接続し、TVTestを2つ起動して別々の番組を見ようとしても、片方のチューナーだけが使用され、2台目を利用できない場合を対象とします。

USBハブ配下で末端ポート番号が重複すると、古いWinUSB実装は別個体へ同じ選択子を付けることがありました。修正版はルートからの経路全体で区別し、経路が取れなければ個別のインターフェースパスを使用します。[機器識別修正](winusb-hub-identity.md)も参照してください。

2026-11-07の `bondriver-v0.1.2` はBonDriver単体の配布であり、この受信サービス側の修正を含んでいませんでした。今回の `windows-multi-tuner-v0.1.2` は両方を含むWindows x64用セットです。

この修正は空いている別個体を使うためのものです。1つの番組を複数台で合成するダイバーシティ受信機能ではありません。

## 更新

1. 両方のTVTestを終了し、そのTVTestが使っているcoaxdも終了します。録画・受信中でないときに行ってください。
2. 実際に起動するフォルダーの `coaxd.exe` と、読み込む `BonDriver_coax.dll` をバックアップして更新します。CLIを利用する場合は `coax.exe` も更新します。
3. 既存INI・チャンネル設定は保持します。複数台から自動選択する場合、チューナーを特定の1台のIDに固定せず、たとえば `[Tuners]` の `terrestrial = ISDBT, cech-zd1j:*, bands=UHF` のように対象の複数台へマッチさせます。
4. 2つのTVTestは同じ更新済み受信サービスへ接続させます。別フォルダーに残っている古いcoaxd.exeが先に起動すると、DLLだけを更新してもUSB識別修正は有効になりません。
5. 受信サービスを起動し直して機器一覧を確認し、2つのTVTestで別々のチャンネルを選局します。

同梱INIは新規導入用のひな形です。設定済みのINIで上書きしないでください。旧形式のUSB選択子を直接固定している場合は、更新後の実際の機器一覧を確認して設定し直します。

## 検証結果（2026-11-07）

- Windowsの機器識別、割り当てプール、Sony DiB8096復調器の関連テストに成功。
- 2台のSony機を模した別クライアントへの自動割り当てテストを追加し、20回反復で成功。1台目の使用中に2台目が取得でき、片方を閉じても他方の占有が維持されることを検証。
- 実際のBonDriver DLLを、Windowsの2つの独立したプロセスへロードし、AF_UNIX経由で異なる模擬チューナーの受信データを同時取得。使用状態一覧が古く、1台目へ `tuner_busy` が返る場合も、2台目を取得できた。
- 前回のBonDriverの26件のテスト・応答待ちキャンセル検証も引き継ぐ。
- 配布するWindows x64版coax/coaxdをビルドし、バージョンを確認。

**実機を複数台接続したRF受信・長時間録画テストは未実施です。** USBケーブルやハブの電気的な問題、アンテナ信号、特定機器だけへ固定した設定については個別の確認が必要です。既存のWindows全体テストの制約は [機器識別修正の検証範囲](winusb-hub-identity.md)を参照してください。

実DLLの検証ツールは `docs/verification/bondriver_two_hosts_abi.go` です。Windows x64上で `go run docs/verification/bondriver_two_hosts_abi.go <テスト用にコピーしたDLL>` として実行します。同名INIをテスト用設定で上書きするため、稼働中のDLLを直接指定しないでください。
