# WindowsのUSBハブ配下で別の機器まで使用中になる問題

## 原因と修正

Windowsの`SPDRP_ADDRESS`はUSBハブ内のポート番号であり、同じホストコントローラーに接続された別ハブ間で重複することがあります。以前は「バス番号＋末端の番号」を選択子にしていたため、別の機器を同一扱いする可能性がありました。

例として、`1-1.1`と`1-2.1`は別の機器ですが、以前の形式ではどちらも`001:001`になり得ます。修正版は`001:001.001`と`001:002.001`のように、ルートからのポート経路全体で区別します。経路が取得できない場合は、機器ごとのインターフェースパスを使用します。

上流の修正[874e730](https://github.com/Till0196/coax/commit/874e7302c24e1977df26fd50fe43dd115a8ca3d3)を、このフォークのv0.1.1ベースへ取り込みました。他の上流変更を一括適用するものではありません。

## 実機なしでの確認

- 3つのハブに2台ずつ接続した想定で、6台の選択子が衝突しない。
- `1`と`10`、`1.1`と`1.10`と`10.1`を区別する。
- 同じ経路でもホストコントローラーが異なれば区別する。
- USB経路を取得できない場合、各機器のインターフェースパスを維持する。
- 6台のうち1台だけを使用したとき、他の5台は使用中にならない。
- 6台を同時に確保でき、1台を解放しても他の5台の使用状態が変わらない。

これらは合成した機器情報と模擬レジストリーによる回帰テストです。Windows実機でのUSBハブ列挙、実際の選局・映像受信、長時間安定性は未確認です。

関連するWindowsテストは、次で再実行できます。

```text
go test ./pkg/usbio/winusb ./internal/coaxd/host/pool ./internal/coaxd/demod/dib8096
```

2026-10-31の確認では、上記は成功し、新しい機器識別・割当のテストは10回の反復でも成功しました。一方、範囲を広げた`go test ./pkg/usbio/...`では、今回変更していない`pkg/usbio/injected`のWindows一時ファイル削除テスト5件が共有違反で失敗しました。この修正で解消する問題とは分けて記録しています。

GitHub ActionsのCIにも手動実行の入口を追加し、実機を使わないLinux側の全体テストと各OS向けの検査を実行できるようにしています。

## 更新時の注意

実際に使用している`coaxd.exe`を、TVTestと受信サービスを終了してから更新してください。これはWindowsのcoax側の機器識別の修正です。WinUSBの再導入やBonDriverの再ビルドを必須にする変更ではありません。

ハブ配下の機器を`001:001`のような旧形式の選択子で直接固定している場合は、更新後の一覧を確認して指定を直してください。例の番号をそのままコピーせず、自分の機器一覧の値を使います。

このフォークで配布している`Tuner = cech-zd1j:*`のひな形には旧形式の番号を固定していません。USB機器自体が認識されない問題や、ケーブル・ハブの電気的な問題は、この修正とは別です。
